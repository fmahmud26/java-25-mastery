# Seven Dimensions

Use every dimension when preparing a topic. Skip none for starred areas (collections, concurrency, VT, JVM, GC).

| Dimension | You should be able to… |
|-----------|------------------------|
| **Theory** | State contracts, invariants, when to choose it |
| **Implementation** | Write idiomatic Java 25 usage without looking up API |
| **Internals** | Explain JDK structure/algorithms at whiteboard depth |
| **Coding** | Solve related interview problems; name the pattern |
| **Performance** | Quote complexity, allocation, scalability cliffs |
| **Real-world usage** | Say what you’d ship in a service and why |
| **Interview questions** | Answer L1–L4 without collapsing into buzzwords |

## Mapping to repo chapters

- Theory / Implementation ← topic `.md` files  
- Internals ← deep-dive notes + this pack’s `internals.md`  
- Coding ← [coding-problems](../coding-problems/) + pack `coding.md`  
- Performance ← [performance-engineering](../performance-engineering/) + pack `performance.md`  
- Real-world ← [modern-java-engineering](../modern-java-engineering/) + pack `real-world-usage.md`  
- Questions ← pack `interview-questions.md` + [java-interview-questions](../java-interview-questions/) for extra drills  

## Quality bar

If you only have Theory + random quiz questions, you’re still at syntax level. **Internals + Performance + L4** is what senior loops test.
